## 實體清單（怪物列舉）— 已【驗】(活快照)

- 數量：清單A `[0xC2D2E0]`（=80 於快照）、容量 `[0xC2D2E4]`(=128)、清單B `[0xC2D2EC]`。
- 存在多個實體指標陣列（含玩家自己），例如快照中 `0x09B5B9xx`；元素為 4-byte 實體指標。
- 容器存取器：`FUN_004181E0(容器,i)`=`*(容器+8)+i*4`；邊界版 `FUN_00418280`(資料`+0xC`, size=`FUN_00418260`)。
- 列舉法(bot 用)：讀清單A數量 N，逐一取實體指標，讀其欄位。

## ✅✅ 攻擊層 in-game 實測結果 (2026-08-11)
- **攻擊 = 兩封包序列**: 先 `0x3C28+dir`(轉向, dir=0-7), 再 `0x3C33`(攻擊)。opcode 由 hook `FUN_004C7D80` 側錄得到。
- 攻擊呼叫配方(ABI 已驗, 呼叫不當機): `cmd=op_new(0x1C0)` [`0x0079A150` cdecl] → `FUN_004C7D80(ecx=cmd, 0, 0x3C33, dir, 0, mx, my, 0, 0)` [__thiscall] → `(*(vtable[1]))(ecx=cmd)` 送出。
- 真實攻擊參數(側錄): a1=0, a2=opcode, **a3=dir(方向)**, a4=0, a5=mx, a6=my, a7=0, a8=0。
- **問題**: 只送 0x3C33 → 怪頭顯示「1」假傷害無效; 加轉向(猜參數)→「Direction Error 77」。天堂客戶端算傷害, 手工組封包參數難全對。
- **改用手法**: 模擬滑鼠點怪(重用遊戲完整攻擊流程+妖精視線)。缺口=**世界(mx,my)→螢幕像素 的投影函數**(待逆向)。遊戲視窗化客戶區 450x423, 玩家在中央~(225,211)。實體物件**不快取螢幕座標**。
- DLL 注入用 write-handle 短命 OK; 但 hook `__thiscall` 函數務必**保留 ECX(=this)** (否則第一次呼叫就當)。

## 🎯 攻擊機制（側錄+逆向 已確認）
- **當前目標全域 `[0x00C2D2B4]`** = 你攻擊的怪的指標（側錄命中；就在角色指標隔壁）。單獨寫入它**不足以**觸發攻擊。
- 攻擊時 **角色 +0x88 = 攻擊命令物件**（vtable `0x008CBCF4`, opcode(+0x18)=`0x42`, +0x34/+0x38=目標座標）; **角色 +0xC8 攻擊中旗標 0→1**。
- **攻擊命令建構子 `FUN_0041E0D0`**（設 vtable 0x8CBCF4、opcode=arg3）。唯一呼叫者=指令處理器。
- **指令處理器 `FUN_00529570(cmdBuf)`**：解析指令緩衝區(格式 `cddhcd`+`hchhhhcs`: target id/opcode/座標)，依 `[0x9A8F00+opcode]` 分類→建命令。**opcode 預設=0x42=攻擊；類別3→FUN_0041E0D0**。
- 觸發攻擊二路：(A) 組 opcode0x42 指令緩衝區餵 `FUN_00529570`(用遊戲命令系統, 最乾淨); (B) 直接 call `FUN_0041E0D0` 建命令+掛 player+0x88。**下一步：小心組參數並用 DLL 實測。**

## 動作/命令系統（其他）
- **`FUN_005ADD70(objId)`** = 由物件ID取得實體指標(id→entity)
- **`FUN_00534310`** = 指令解析執行(AI/腳本 move-to-target)
- **`FUN_005A6F20`/`FUN_005A7CF0`/`FUN_0041E330`/`FUN_0044BAA0`/`FUN_0046B960`** 皆呼叫攻擊決策 `FUN_005ABC90`
- **`FUN_004C7D80`(cmd建構子)**：`(this, val, opcode, b15, b16, x, y, targetObj, ?)`
  - opcode→ this+0x18(short)；座標 x,y→ FUN_0040D510 存入；target→ this+0x1C；vtable=`0x8D0F18`
  - this+0x14=狀態byte；this[8]=`*(0x9A8F0C+opcode*4)`(opcode→handler表)
  - 執行：`(*(*cmd+4))()`（vtable+4 = 執行/送出）
- 已知 opcode：`0x2a7f/0x2a81`=移動(click-to-move, FUN_00418020)；**`0x4E0`=疑似攻擊**；0xa9,0x68,0x8b7,0x1cee=其他
- **`FUN_005ABC90`(cmd)**：攻擊決策——依 this+0x14 狀態，經檢查鏈後對目標座標發 `0x4E0`
- **候選 射程/視線 檢查**：`FUN_005AF2F0`、`FUN_0041E7B0`、`FUN_005AB2A0`、`FUN_005ABE00`（妖精不射牆的關鍵，待確認）
- **`FUN_0046B960`**：迭代目標清單發動作（多目標）
- opcode→handler 表：`[0x009A8F0C + opcode*4]`
- **下一步**：確認 0x4E0=攻擊；找「對指定目標實體發動攻擊」的高階入口(click-attack)；動態驗證(在遊戲內呼叫看是否真的攻擊)
